# Changelog

All notable changes, newest first. Dates are the day the work landed.

## 2026-10-12

- The admin console's new-user cost cap takes any amount (the field stepped by 0.5, so the browser refused values in between).
- A main chat with forks has Delete all chats in its sidebar menu: it removes the main chat and every fork in one transaction (`POST /api/chats/:id/delete-all`), after a confirmation that opens on Delete all.
- The spending cap no longer reserves each reply's worst case up front (16k output tokens at the long-prompt rate, which let a guest start only four of ten forks). A reply starts while its estimated input fits under the cap and is metered as it streams; when spend plus the user's live replies reaches the cap, every running reply of theirs ends with "quota exceeded", keeping its text. The real usage is what is charged, so the cap can be overshot by about one streamed chunk per reply. D22 amended.
- The header's usage bar picks up the new account's figures after signing in.
- The usage bar's tooltip shows over the fork tab strip (the strip covered it), the New chat tooltip opens leftward instead of being cut off at the sidebar's edge, and Declare winner opens focused on its button (Enter confirms) with white text.
- A usage bar on the header's bottom border shows spend against the cap (hidden when there is no cap); hovering its 12 px strip, or focusing it, shows the exact amounts. It refreshes when a reply ends (`GET /api/usage`). Every tooltip now appears and disappears instantly. Plausible loads from a plain deferred script tag instead of `next/script`, which took 1.9 kB off every route; the chat route measures 203.63 kB.
- Guests: a visitor without a session is a guest instead of being sent to sign in. Guests chat on Haiku only (the other models show greyed out, and the server refuses them), under a $0.25 cap (`GUEST_COST_CAP_USD`) with Explore on; new guests are limited per address. The sidebar footer's Sign out slot is Sign in for a guest, and signing in moves the guest's chats into the account. Idle guests are purged after 30 days. Migration 0003 adds `users.is_anonymous`. The sign-in page offers "Continue as a guest". ADR-0004 amended.
- A new chat sits at `/c` until its first send, which rewrites the address to `/c/<id>` in place (nothing remounts). `/`, `/c/new` and the installed app open `/c`. ADR-0005 amended.
- The app has no name of its own: the old name is gone everywhere (titles, the manifest, the sidebar, the sign-in and invite pages, the system prompt, storage keys, identifiers and docs); where a name is needed it is "Chat". The landing page is gone too: `/` opens a new chat (sign-in first), and the installed app starts there. The composer's placeholder reads "Send a message". Saved themes, drafts and model choices start fresh because their storage keys changed.
- Switching the theme recolours everything in the same frame: buttons and rows with a colour transition (the sidebar buttons, the open chat's row, Send) used to ease into the new theme about 150 ms behind the rest of the page.
- Settings usage: a group with a single model shows no total of its own, since the model row would only repeat it.
- Settings usage table: model names in the foreground colour, each total sits tight above its models, and the groups get even spacing.
- Earlier messages load by themselves when the reader scrolls near the top of a long chat (no "Show N earlier messages" button); the reading position stays put while they land above.
- A chat that fits on screen never shows Jump to latest: an upward wheel, drag or scroll key only stops auto-follow when the thread can scroll.
- Deleting the open chat moves to the next tab over (or the one before, if it was the last), as closing a tab does; a chat with no tabs still opens a new chat.
- Settings usage: Explore is laid out like Chats, a total row with one row per model under it, instead of a fixed "Haiku" caption.
- Search shows skeleton rows from the keystroke, through the 200 ms debounce, until that query's results are in; the previous query's hits no longer linger meanwhile.
- Explore options also appear for a menu of ideas or suggestions the user could pick from, even when they could do several (a reply offering three random decisions got no button). Tips that together serve one goal still don't count. Checked on 10 replies, 3 runs each: 30/30, against 27/30 before.
- While Haiku reads the last reply for options, the border above the input pulses lightly (not with reduced motion).
- Picking a model from the desktop menu puts focus in the message input, ready to type (Escape or a click away still returns it to the picker).
- The keyboard hint line under the composer is gone; the Search and New chat buttons show their shortcuts (⌘K, ⌘⇧O) in their hover tooltips.
- While the Explore button is up, its dashed border turns slowly clockwise as a whole (faster while it waits or forks; none with reduced motion).
- In the Explore options sheet, a click or tap anywhere on an option outside its title and message fields picks or drops it.

- A click or tap on the open fork tab opens its menu (as a right-click does); a second press closes it.
- A reply's ⋯ offers Duplicate: a new fork tab of the main chat holding the chat up to and including that reply (a fork duplicates as its sibling; counts toward the ten-fork cap, and the item hides once the main chat has ten). `POST /api/chats/:id/duplicate`.
- Every clickable control shows the pointer cursor: menu items (they had `cursor-default`) and every enabled button, tab and option (Tailwind's reset gives buttons the arrow).
- A reply still rate limited after its four automatic tries no longer offers Try again.
- Modals and menus open at once: the first open of search, rename, delete, the scenarios panel, the fork sheet, a tab's menu or a ⋯ menu waited about 310 ms (React holds a Suspense boundary's content back 300 ms after its fallback; every `next/dynamic` control suspended on first mount). Chunks now load first and the loaded component renders directly (5 to 25 ms measured); the dialogs' chunk is preloaded in idle time.

The chat route measures 203.76 kB.

- Declare winner closes as soon as the server answers: it used to wait for Haiku to finish reading the winner's last reply, which took seconds. The winner's Explore button pops up when Haiku's count arrives, as after any reply.
- No more blink on the first click of a lazily loaded control (a reply's or your message's ⋯, a sidebar row's ⋯, the model picker, Scenarios, the header title): while its chunk loads, the stand-in shown is the same button, not a blank (the reply's ⋯ vanished for about 300 ms) or a disabled one (dimmed); stand-ins with nothing to do are `aria-disabled` rather than `disabled`. `forkChat` loads with the fork sheet, which keeps the chat route at 204.62 kB.
- Settings: Chats usage is broken down by model (a fallback's serving model counts as its own), under the chats total.

## 2026-10-09

- Explore options: after a reply that lays out alternatives, a button above the composer forks the chat once per option. Claude Haiku 5.5 reads the final reply (only that) as a side effect of the reply and proposes a tab title and a first message per option; a click opens a sheet with every option picked, where they can be deselected, retitled and reworded, or one instruction applied to every prompt, and its button forks them. Each fork copies every parent row, shows "Forked from main chat", and asks the parent's model at the parent's effort; the first fork writes the cache entry for the parent's final reply and the rest read it, and a first reply that fails before the API begins a message is retried after 1 s, 2 s and 4 s. Forking spends the options, so the button goes away. Folder tabs on the composer's input list the main chat and its forks (the open tab joins the input; the Explore button widens into the row and the tabs grow into their slots; a chat with forks shows the tabs there instead of the button), drag-ordered with a mouse or pen; in the sidebar the parent carries a fork icon and lists its forks nested beneath it while it or one of them is open. The sheet opens on its instruction input (Enter applies it, Shift+Enter forks). Each tab closes with its ×, and comes back when the chat is opened from the sidebar; Ctrl+Shift+] and [ cycle the tabs; a right-click on a tab offers Declare winner on a fork (the fork stays alone with its history; the main chat and the other forks are deleted), Delete forks on the main chat, and Delete chat, each confirmed in a dialog (`chats.tab_hidden`). Haiku lists options only when the reply is a choice: explained alternatives the user could pick between, even when the reply recommends one; fewer than two count as none; the rewrite leaves titles alone unless the instruction is about them. Declaring a winner reads its last reply so it can be forked at once. At most ten forks per chat, none of a fork. `chats.forked_from`, `fork_position`, `fork_order` and `messages.thinking`, `fork_options` join the schema. ADR-0006.
- The per-user running cap (3) and the send window (20 a minute, 300 a day) are removed: the cost cap is the only limit. The feedback and long-chat seed endpoints keep their windows.
- The migration history is collapsed into one initial migration (`0000_init`: the schema plus the search index and its triggers), since nothing has shipped. Every existing database must be recreated: delete the file and let boot rebuild it.
- In development the browser console shows each Haiku call behind Explore options: the system prompt, the user turn, the parsed answer (or the raw text), tokens, and timings (the page's wait from the reply ending to the options arriving, the Haiku call, the server's whole detection, and how long the options request was held). Production sends none of it.
- Explore options detection runs Claude Haiku 5.5 with adaptive thinking at medium effort: at low effort it never thinks and read a menu of ideas as eight alternatives every time; at medium it thought, answered "none" in 4 of 5 runs, and was as accurate as high and faster; plain replies and real choices cost the same. The prompts it writes are one sentence each. The sheet's rewrite stays at low effort with thinking off.
- The Explore button follows Haiku as it writes: the answer puts the option count first and streams to the page as JSON lines, so the button pops up from behind the composer's top border, to where Jump to latest sits (which moves above it), as soon as the count says there are options. Otherwise it stays tucked away: no waiting state, and nothing shown for a fork, ten forks already, an edit in progress, a reply still streaming, or no options. A click before the list is complete pulses until it is (at most 5 s, or an error), then opens the sheet with what has arrived.
- Typing a character with nothing focused goes to the composer: it takes focus on the keydown so the character lands in it, at the end of any draft. Not with a modifier held, not for Space or special keys, and not while a dialog, a menu or the phone sidebar is open.

## 2026-10-08

- Chat groups are removed. The sidebar is Pinned, then Chats again; a chat row's ⋯ menu has Pin, Rename and Delete (no Move to); `/api/groups` and `groupId` on `PATCH /api/chats/:id` are gone. Migration 0010 drops `chat_groups` and rebuilds `chats` without `group_id` (SQLite cannot drop a column that carries a foreign key); chats that sat in a group stay, ungrouped. Migration tests take a database that ran the original 0008, one at 0009 and a fresh one to the same schema with every chat, message and generation kept. The chat route measures 196.67 kB against the 205 kB gate.

Fixes from the 2026-10-08 codebase review, one commit per finding.

- Data integrity: a failed reply offers Try again (and its 429 countdown) only while it is the chat's last turn, so retrying it can no longer wipe a later message that never reached the server; retrying a refused Edit or Regenerate sends the attempt's original `replaceFromMessageId`, so the server replaces what the view already dropped instead of appending; sending in a pinned or grouped chat keeps it in its section (`upsert` merges); a pin or move that fails or is refused moves back, and a late failure never undoes a newer accepted change.
- Cost and abuse: the chat POST admits, starts and charges the limiter in one synchronous step after the replace-path await, so parallel regenerates can no longer pass the 3-running cap or the per-minute window, and a duplicate POST from the owner attaches without the gates (`src/relay/admission.ts`); invited users get `DEFAULT_COST_CAP_USD` (5) when the cap is left blank and "no cap" is an explicit `"none"`; a crashed scripted or replayed run settles at zero cost; a Haiku reservation is priced for Haiku (fallback targets count only when `modelParams` sends fallbacks), about $0.04 instead of $0.40.
- Security: invite tokens stay out of Plausible (`script.exclusions.js`, `/invite/**`), Sentry events and breadcrumbs, server request-error reports (`src/shared/redact.ts`), and Referer headers (`Referrer-Policy: no-referrer` on `/invite/*`); production refuses to start without `BETTER_AUTH_SECRET` (it only warned, and with `TEST=1` better-auth fell back to its public default secret), and the warning no longer fires during `next build`.
- Database: migrations run through `applyMigrations` (`src/db/migrator.ts`), which turns foreign keys off outside the transaction (SQLite ignores the pragma inside one, so a drizzle-kit table rebuild would have cascade-deleted every child row) and runs `foreign_key_check` before commit; migration 0009 rebuilds `chats` so `group_id` is `ON DELETE SET NULL` on databases that ran 0008 before it was edited.
- Streaming and transport: an error event mid-stream is classified by its type like the replayed fixtures (rate limits get their countdown, a 500-class `api_error` is retryable, the message is the API's text, not JSON); a POST that keeps failing at the network level backs off and gives up after three re-POSTs with "Lost the connection."; a request waiting for response headers times out after 15 s and `online`/visible retries it at once, and `resumeAll` applies events queued in a hidden tab first; a stop that fails or hangs settles `false` within 15 s, so Stop and Esc work again; each rate limiter starts one sweep timer, once (every feedback POST added another), and the send limiter is swept too.
- Rendering: a code fence nested in a list or quote stays plain until it closes instead of re-highlighting on every chunk; CRLF replies split into blocks; a fence in a list led by a label line stays in the list, an indented top-level fence drops its indent, and the incremental split matches a full split at every prefix (an invariant test); character references render decoded (`&amp;`, `&mdash;`, `&nbsp;`) except in code and after a backslash, and are decoded before `safeHref` checks a link; diff blocks get their inserted, deleted and changed colours (each at least 5.1:1 on the code background).
- Accessibility: the phone sidebar is inert when closed and a modal dialog when open (it keyed off the desktop state, so neither ever applied on a phone), takes focus when it opens and returns it to the menu button when it closes; a ⋯ menu returns focus to its row's ⋯ on close (the real trigger unmounted before Radix could focus it); search opened from the phone sidebar returns focus to the menu button; the model picker is a Radix menu at `md` (radio items and a checkbox item) and a radio group in the phone sheet, so the keyboard reaches every model and Think harder. The chat route measures 198.12 kB against the 205 kB gate.
- Ops and harness: the CI e2e job gets the standalone build as a tarball (upload-artifact v4 drops hidden files and symlinks, so `.next/standalone/.next` and `node_modules/.pnpm` never arrived) and the workflow token is read-only; the image starts as root only to hand the `/data` volume to `node`, then runs the server as `node` via `setpriv` (a root-owned Railway volume left SQLite unable to open the file); `.env.example` works with `docker --env-file` (no `DATABASE_PATH`, comments on their own lines); `pnpm test:shutdown` passes again (it matched `event:` lines the server stopped sending), targets only the listener, and cleans up its servers; `data/` is ignored and the committed shutdown-test output is untracked; the e2e specs find the sidebar by `aside[aria-label="Chats"]`.

## 2026-10-07

- The model picker's rows have more vertical padding (10 px above and below the two lines of text), so the name and its blurb no longer sit tight against the row edges.
- Claude Haiku 4.5 is removed: nothing had been saved with it, and Haiku 5.5 is cheaper on every line with a 1M window and effort-steered thinking. With it go the `budget_tokens` thinking path, its rates and speed seed, its picker copy and the "Extended thinking" wording; the replay fixtures are regenerated for Haiku 5.5 (`pnpm fixtures`) and the specs that chose Haiku 4.5 choose 5.5.
- Chat groups: a chat row's ⋯ menu has "Move to" with the user's groups, "New group…" and "Remove from group"; each group is a collapsible section in the sidebar (the collapse is remembered server-side) with its own ⋯ menu for Rename group and Delete group (deleting keeps the chats, which return to the main list). Groups live in `chat_groups` and `chats.group_id` (migration 0008) behind `POST /api/groups`, `PATCH`/`DELETE /api/groups/:id` and `groupId` on `PATCH /api/chats/:id`; the list orders Pinned, then groups, then Chats, and a pinned chat shows under Pinned. Covered by a Playwright test that creates a group from the menu, collapses it across a reload, and removes the chat again.
- Pinned chats: Pin and Unpin in a chat row's ⋯ menu (and by right-click); pinned chats sit under a "Pinned" heading at the top of the sidebar, the rest under "Chats" once anything is pinned. The flag is a column on `chats` (migration 0007), set through `PATCH /api/chats/:id`, and the row moves at once with the request behind it. Covered by a Playwright test that pins, reloads, and unpins.
- A right-click anywhere on a chat row opens its ⋯ menu in place of the browser's context menu.
- Tooltips centre under their button and shift to the start or end only when centred they would leave their container (the sidebar, the header or the composer, marked `data-tip-boundary`; else the viewport): the alignment is measured just before the tooltip shows, from the hidden pseudo-element's width. The hand-placed `tipAlign="end"` on the theme, sign-out, close, feedback, send and ⋯ buttons is gone; `tipAlign` remains as an override.
- Claude Haiku 5.5 (`claude-haiku-5-5`, released 2026-10-07) is in the picker as "Fastest replies at the lowest cost, with effort levels": 1M context, adaptive thinking steered by effort (low, or high for Think harder) with bound thinking blocks, no server-side fallback (none is documented for it). Pricing follows its two tiers, $0.10 in / $0.50 out up to a 100k-token prompt and $0.50 / $2.50 above it (cache write $0.125 / $0.625, cache read $0.01 / $0.05): `ratesFor` takes the prompt size and `costOf` passes input plus cached tokens, so a long-prompt request is billed at the higher tier, and the cap reservation prices against the dearer tier. Haiku 4.5 stays as "Quick replies, previous generation". Source: the model's page on the Claude platform docs.
- A chat row stays highlighted while its ⋯ menu is open: the menu is a portal, so moving the pointer onto it ended the row's hover and the row went blank under an open menu.
- Search shows one pulsing skeleton row while the first results load; hits already shown stay put while a refinement loads.
- Rate-limited replies retry by themselves with exponential backoff: the server's retry-after is the base (15 s when it gives none, never under 2 s), doubled per attempt, capped at two minutes, four automatic tries in all; the footer reads "Rate limited. Retrying in 12s (try 2 of 4), or Try again now." with the inline Try again for an immediate manual retry, and after four refusals "Still rate limited after 4 tries. Try again." The attempt count travels with the replacement message (`retryAttempt`), so a manual Try again also continues the streak and a reply that succeeds resets it; a saved error from an earlier session never auto-retries on open. Covered by a unit test of the schedule and a Playwright test that watches two refused automatic tries and the third go through.
- Queued messages: a message sent while a reply streams no longer bounces off a disabled composer. It joins the chat's queue, shows where it will land (a dashed bubble under the thread with Edit and Remove), and goes out as soon as the reply ends; several can wait, and they go out one per finished reply. While a reply streams the composer shows Stop and a Queue button side by side; Enter queues. An edit cannot be queued (it would replace turns still being written) and still waits for the reply. A reply that fails keeps the queue for the user to decide. The queue lives in the client store per chat (`ChatState.queue`) and is covered by a store test and a Playwright test (two queued during `slow_tokens`, one removed, the other sent when the reply finished).
- The ⋯ buttons on chat rows and message rows have a visible hover: the ghost button's hover tint was the same colour as the hovered row, so pointing at the button changed nothing; it now takes a wash of the foreground (10 % in light, 15 % in dark, with explicit `dark:` variants because the ghost variant's own `dark:hover:bg-muted/50` outranks a plain `hover:` class) and the full foreground colour, and stays that way while its menu is open.
- Rate-limited footer: "Try again" is an inline control in the sentence ("Rate limited. Try again in 12s.") and the Retry button is gone, so the footer appearing adds a line of text, not a 44 px button row, and nothing below it shifts.
- Rendering (#12, #23, #24, #25, #26, #53, #67): code is tokenised once with a CSS-variables theme (`createCssVariablesTheme` from `@shikijs/core`, now a direct dependency since `shiki/core` does not re-export it; `code.css` carries the light and dark palettes), so a theme switch is a repaint and the worker does half the work; a fenced block indented inside a list item stays in the list block, so marked nests it and Copy gets the code without the indent; while a reply streams only the last block is re-split (`splitBlocksIncremental`, a small cache outside React), since every earlier block is final; a streaming table always drops its last, possibly unfinished row and keeps fixed column widths until it closes, so rows no longer appear and vanish and columns no longer re-flow per chunk; a streaming fence renders as the same contained line groups as a closed one, each group keyed on its own text, so a delta changes one group's text node and lays out one block; the caret follows prose only (paragraphs, headings, the last list item, the last quoted paragraph), so a trailing list, code block or table gets no empty line under it; a saved reply shows a fallback divider only where the live stream did (after text), never for a pre-output fallback.
