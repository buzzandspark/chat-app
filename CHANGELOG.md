# Changelog

All notable changes, newest first. Dates are the day the work landed.

## 2026-10-07

- Fix (critical): a second New chat in the same session wiped itself. `/c/new` was a mounted page that Next kept alive in a hidden Activity; brought back with a fresh server id, the view re-hydrated an empty list on every render and never replaced the URL, so the thread went blank while the reply streamed into nothing. There is no "new" view any more: New chat navigates straight to `/c/<uuid>` generated on the client (sidebar button, ⌘⇧O, delete, context-full, login, invite, demo), `/c/new` is a 307 alias in `proxy.ts` for bookmarks, an id the server has never seen renders an empty usable view instead of a 404, and the first send no longer calls `router.replace` (which also removes the 600 ms skeleton remount after the first message). `e2e/new-chat.spec.ts` reproduces the exact sequence (send, New chat, send) and checks both threads, both URLs and the sidebar.
- Security and correctness fixes from review: anonymous users are forced to the `demo` role by a database hook and the public anonymous sign-in endpoint returns 404 (only `/api/demo/start` creates them, server-side), so nobody can obtain an uncapped live-model account; the engine now emits its terminal event, settles cost and releases the quota reservation even when its rows have been deleted mid-stream, and chat delete and truncate wait for running generations to settle before removing rows; `resume` and the duplicate-POST path check ownership before serving any buffer; `.env` files are excluded from the Docker build context; `/api/demo/start` (per address), `/api/feedback` (signed-in users, strict timings schema) and the long-chat seed are rate limited.
- Sidebar: the chat menu sits inline at the end of each row (flex, space-between) instead of floating above it; opening or renaming a chat highlights it without moving it to the top, only sending a message does.
- Fix: after the first message in a new chat the URL was swapped with `history.replaceState`, which Next's router ignores; a later "New chat" was then a no-op that left the old thread on screen. The view now navigates with `router.replace`.
- Modals: a central `ModalProvider` mounts every dialog (search, feedback, rename, delete, scenarios) and keeps it mounted through its exit animation, so closing animates instead of vanishing; on phones every dialog is a bottom sheet that slides in and out, and the sidebar takes the whole screen and closes when a chat is chosen; on desktop the sidebar stays docked.
- UI fixes from review: sends are blocked while a reply streams; `tailwind-merge` is back (the small merger dropped `left-1/2` and `inset-*` classes, which put dialogs off screen and misshaped sheets), size gate 200 kB; the desktop sidebar stays docked when following a link; the composer is focused on a new chat on desktop; the chat title in the header opens rename; the scenario panel is an icon in the composer toolbar; every icon-only button has a CSS hover tooltip (`IconButton`); the model picker no longer flashes an outline on open.
- Fix: "Cannot update a component (ChatShell) while rendering a different component (ChatView)". The chat store is now one instance per shell provided through context (fresh per server render, long-lived on the client) and render-time seeding notifies subscribers in a microtask. The server no longer accumulates rendered chats in a module singleton.

## 2026-10-06

- Polish (step 4): edit-last-message with server-side truncation, regenerate that replaces the reply on the server, drafts per (user, chat) in localStorage, the D20 latency popover with persisted client stamps, sidebar rename/delete and ⌘K search behind one responsive dialog (bottom sheet on phones, modal at md), header title, keyboard shortcuts, a polite live region, a dev-only `/preview` gallery at 390 px, the opt-in per-model cache test (`pnpm test:cache`).
