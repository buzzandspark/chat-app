# Changelog

All notable changes, newest first. Dates are the day the work landed.

## 2026-10-07

- Scroll (D14, D16): auto-follow no longer disengages when the content shrinks (a long thinking block collapsing) because the `movedUp > 48 px` clause is gone and only a scroll that leaves the end disengages; the scroller itself is observed by the `ResizeObserver`, so the thread stays pinned when the Android keyboard opens (the review measured the last row's visible height dropping from 300 to 38 px); the initial scroll to the end runs in a layout effect, so a long chat paints already at its end instead of oldest-first and then jumping; `content-visibility: auto` on rows is gated on scroll anchoring that works (a flag on `<html>`): WebKit answers `@supports (overflow-anchor: auto)` and even a synthetic anchoring probe with yes, yet does not anchor when skipped rows above the viewport take their real size (measured: a 300 px scroll moved content by 479 to 683 px, the iPhone Safari jump the review reported on 38 of 40 steps), so the engine is identified by vendor and rows there are always laid out. Loose list items render their paragraphs as `<p>` instead of one run-on line. `e2e/scroll.spec.ts` covers the thinking collapse, the viewport shrink, the first painted frames of a 200-message chat and even scroll-up steps; a unit test covers loose and tight lists.
- Server: chat search filters in SQLite (`lower(content) LIKE ? ESCAPE '\'` over the stored JSON, with `%`, `_` and `\` escaped) and JSON-parses only the matching rows; before, every message of every chat was parsed in JavaScript on each keystroke, about 30 MB for a large history. The three indexes the hourly demo purge was missing landed with the resume migration.
- Layout decided in CSS, theme before first paint: the sidebar's desktop dock and phone overlay are separate states, so the server renders the dock at `md` and a desktop cold load no longer shifts (the review measured CLS 0.20 when the dock appeared only after hydration); off screen on a phone the sidebar is `inert`. The theme bootstrap is a raw inline `<script>` in the document head ahead of every Next script (next/script's `beforeInteractive` goes through Next's `__next_s` queue, after the first paint for dark-mode users); it exists only in the server HTML (`ThemeScript` renders it from a server snapshot and drops it after hydration), so a client-render fallback never creates a script element and React's "Encountered a script tag" warning cannot fire. `e2e/perf.spec.ts` gains a desktop cold-load CLS check (0 shifts, CLS 0, dock present in the server HTML) and `e2e/theme.spec.ts` checks the stored theme is applied before `first-paint`, that every script ahead of it in the document is an `async` chunk, and that it precedes the RSC payload.
- Resume protocol (D2): each partial write and the final write now record the producer seq the saved content covers (`messages.last_seq`, migration 0002); the page's rows, `GET /api/chats/:id` and the resume `snapshot` carry it. The client seeds its cursor from it and resumes after that seq, so a reload mid-stream or a second tab shows the reply once (the review measured 6,414 characters against 5,444); a snapshot is applied by seq and status, so a finished local reply is never replaced by a stale `streaming` row and a late replay of already-seen deltas is dropped; a delta for a block the client has never seen creates it (an empty block is not saved with a partial). Watchdogs on both hops: the client drops a connection with no bytes for 25 s (the server writes a keepalive every 15 s) and resumes from its last seq with the usual backoff, with the "Reconnecting" state showing; the engine ends a generation whose upstream sends nothing for 60 s as `interrupted { reason: "upstream" }` instead of holding it open. The three indexes the hourly demo purge was missing (`generations.user_id`, `feedback.user_id`, `users.created_at`) ship in the same migration. Tests: store seq rules and self-healing deltas, transport watchdog, engine covered-seq atomicity and idle timeout (unit); reload mid-stream yields the exact final text and a second tab ends with the same text (e2e).
- Bundle: Radix `Slot` leaves the first paint (the button's `asChild` served two links, which now use `buttonVariants` directly), an unused error class and store method are gone; the chat route is 198.82 kB gzipped against the 200 kB gate.
- Chat switching, prefetch on intent (D21): hovering, focusing or touching a sidebar row, and opening the sidebar for its top five chats, warms the route shell and fetches the chat's rows from `GET /api/chats/:id` into the store, so the click that follows renders from memory. `e2e/perf.spec.ts` now records click-to-thread in animation frames after the tap for a loaded chat, a hovered chat and a cold chat (Pixel 7, CPU 4x, Fast 3G): a loaded chat highlights its row in the first frame and paints its thread in the second (26 to 28 ms), a hovered chat the same (31 ms), and a tap that beats the sidebar's own prefetch shows the highlight in frame 1, the skeleton in frame 2 and the rows when the fetch lands (344 ms). The unused shadcn button variants (`link`, `xs`, `icon-xs`, `icon-lg`, button groups) are dropped; the route is 199.93 kB gzipped against the 200 kB gate.
- Fix: retry after a rejected send always failed with 409. The retry POST carried no text, and after a refused first POST (429, 503, 402) the server had no user row to retry from; the client now sends the user message's text with a retry and the engine inserts the missing row as it does on a first send.
- Chat switching, client store first (ADR-0005): the chat route renders from the client `ChatStore` at once (`ChatView` sits in the static shell and reads its id from `useParams()`); the server's rows arrive through a Suspense child, `SeedChat`, that reconciles them into the store during its render (local in-flight messages win, a finished local reply is never replaced by a stale `streaming` row, optimistic messages the server has not listed yet stay). Per-chat settings (model, Think harder, scenario) live in the store, so nothing resets on a remount; the first send does not remount the view. `GET /api/chats/:id` returns the rows the page seeds with. New chats are created in the store as empty, so they never show a skeleton. Measured on the production build with 100 ms emulated latency, click to thread painted for a chat already in memory: 126 to 130 ms before (every switch was a round trip), 27 to 30 ms after (the frame after the click); cold chats stay at one round trip (127 to 131 ms) behind the skeleton. `e2e/chat-route.spec.ts` covers the no-remount first send, settings surviving a switch, a refused first POST keeping the typed message, and a revisit with no request.
- Chat switching, immediate feedback (D21): the clicked sidebar row is highlighted and the header title switches on click through an optimistic pending-chat store, before the router commits; the thread skeleton and a composer placeholder mirror the real layout class for class, so the composer no longer collapses from 115 to 56 px while a cold chat loads (desktop keeps its 135 px, hint line included, which is now shown by CSS at `md` with hover instead of after hydration). Measured on the production build with 100 ms emulated latency: row and title in 9 to 13 ms, skeleton by 24 to 31 ms; the thread itself still waits for the round trip (130 to 330 ms) until the next entry.
- Fix (critical): a second New chat in the same session wiped itself. `/c/new` was a mounted page that Next kept alive in a hidden Activity; brought back with a fresh server id, the view re-hydrated an empty list on every render and never replaced the URL, so the thread went blank while the reply streamed into nothing. There is no "new" view any more: New chat navigates straight to `/c/<uuid>` generated on the client (sidebar button, ⌘⇧O, delete, context-full, login, invite, demo), `/c/new` is a 307 alias in `proxy.ts` for bookmarks, an id the server has never seen renders an empty usable view instead of a 404, and the first send no longer calls `router.replace` (which also removes the 600 ms skeleton remount after the first message). `e2e/new-chat.spec.ts` reproduces the exact sequence (send, New chat, send) and checks both threads, both URLs and the sidebar.
- Security and correctness fixes from review: anonymous users are forced to the `demo` role by a database hook and the public anonymous sign-in endpoint returns 404 (only `/api/demo/start` creates them, server-side), so nobody can obtain an uncapped live-model account; the engine now emits its terminal event, settles cost and releases the quota reservation even when its rows have been deleted mid-stream, and chat delete and truncate wait for running generations to settle before removing rows; `resume` and the duplicate-POST path check ownership before serving any buffer; `.env` files are excluded from the Docker build context; `/api/demo/start` (per address), `/api/feedback` (signed-in users, strict timings schema) and the long-chat seed are rate limited.
- Sidebar: the chat menu sits inline at the end of each row (flex, space-between) instead of floating above it; opening or renaming a chat highlights it without moving it to the top, only sending a message does.
- Fix: after the first message in a new chat the URL was swapped with `history.replaceState`, which Next's router ignores; a later "New chat" was then a no-op that left the old thread on screen. The view now navigates with `router.replace`.
- Modals: a central `ModalProvider` mounts every dialog (search, feedback, rename, delete, scenarios) and keeps it mounted through its exit animation, so closing animates instead of vanishing; on phones every dialog is a bottom sheet that slides in and out, and the sidebar takes the whole screen and closes when a chat is chosen; on desktop the sidebar stays docked.
- UI fixes from review: sends are blocked while a reply streams; `tailwind-merge` is back (the small merger dropped `left-1/2` and `inset-*` classes, which put dialogs off screen and misshaped sheets), size gate 200 kB; the desktop sidebar stays docked when following a link; the composer is focused on a new chat on desktop; the chat title in the header opens rename; the scenario panel is an icon in the composer toolbar; every icon-only button has a CSS hover tooltip (`IconButton`); the model picker no longer flashes an outline on open.
- Fix: "Cannot update a component (ChatShell) while rendering a different component (ChatView)". The chat store is now one instance per shell provided through context (fresh per server render, long-lived on the client) and render-time seeding notifies subscribers in a microtask. The server no longer accumulates rendered chats in a module singleton.
